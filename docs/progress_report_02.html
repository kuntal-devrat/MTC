1. Project Overview & Problem Statement Section 1

1.1 Background & Motivation

Tiny Machine Learning (TinyML) has achieved remarkable progress in enabling deep neural network inference on ultra-low-power microcontrollers (MCUs) with memory budgets as low as 256KB to 512KB of SRAM. Widely adopted frameworks such as Google's TensorFlow Lite for Microcontrollers (TFLM) and ARM's CMSIS-NN have formalized optimized forward execution kernels.

However, virtually all existing edge solutions operate under a rigid "train-in-the-cloud, deploy-frozen" paradigm. While these static models perform effectively under stationary training distributions, modern Internet of Things (IoT) edge deployments operate in dynamic, non-stationary physical environments where fixed weights degrade over time.

1.2 The Problem: Limitations of Frozen On-Device Models

Deploying permanently frozen models on embedded edge hardware creates three severe operational bottlenecks:

  • Sensor Degradation & Drift: Mechanical sensors, MEMS accelerometers, gas sensors, and electrochemical probes experience physical wear, thermal stress, and aging. A model trained in a factory baseline becomes progressively inaccurate over months of operation unless continuous recalibration is performed directly at the sensor node.
  • Privacy & Air-Gapped Compliance: In applications governed by strict regulatory frameworks (e.g., HIPAA for biometric wearables, GDPR for personal audio, or air-gapped industrial facilities), transmitting raw telemetry data to external cloud servers for retraining is legally prohibited or violates cybersecurity policies.
  • Bandwidth & Energy Bottlenecks: Streaming high-frequency sensor streams (e.g., 100Hz 3-axis vibration data) over wireless cellular or satellite links rapidly exhausts battery reserves. Transmitting raw data consumes orders of magnitude more energy than executing local backpropagation on MCU hardware.

1.3 Proposed Solution: The Micro-Train-Compiler (MTC)

Micro-Train-Compiler (MTC) is a domain-specific source-to-source compiler implemented in Rust. Instead of embedding a heavy dynamic runtime or tape-based autograd engine onto the microcontroller, MTC shifts all computational differentiation, fixed-point scaling, memory layout optimization, and stability checks entirely to compile time.

MTC ingests a declarative JSON neural network architecture, validates its dimensional integrity, analytically synthesizes exact gradient equations using reverse-mode automatic differentiation, verifies numerical ranges via interval arithmetic, and emits standalone, zero-dependency C99 source code specifically optimized for 32-bit microcontrollers such as the ESP32 (Xtensa LX6, 240MHz, 520KB SRAM).

Core Design Objectives:
  • Zero Runtime Dependencies: Emits pure C99 with standard math headers (no OS, no dynamic allocator).
  • Static Peak SRAM Watermark: Enforces total training memory footprint strictly under 64KB.
  • Guaranteed Numerical Stability: Compile-time interval analysis prevents integer overflow in Q15 arithmetic.

3. Proposed Methodology & Compiler Pipeline Section 3

3.1 Five-Phase Compilation Pipeline Overview

The MTC compiler is organized as a sequential multi-pass pipeline where each pass operates on a strongly-typed Intermediate Representation (IR). The compilation stages progress deterministically from high-level user configuration to target C99 source files:

Phase Pass Name Input Data Structure Output Product / Artifact
Phase 1 Model Parser & Validator JSON Model Specification Verified Forward Computation DAG (IrGraph)
Phase 2 Reverse-Mode Autodiff Forward IrGraph Combined Forward + Backward Gradient DAG
Phase 2b Numerical Range Analysis Combined Gradient DAG Bounded DAG with Q15 Stability Verification
Phase 3 Static Memory Planner Annotated DAG + Node Lifetimes Static Offset Map (< 64KB Total Watermark)
Phase 4 C99 Code Emitter Memory-Mapped IR Graph Standalone C Files (mtc_model.c, mtc_train.c)

3.2 Technical Deep Dive into Pipeline Passes

  • Phase 1: Ingestion & Semantic Validation: Reads the architecture JSON into typed Rust structs (ModelConfig). Statically checks that layer dimensions chain correctly ($W_1.\text{out} = W_2.\text{in}$), rejects empty networks, ensures activation functions have valid preceding layers, and verifies supported loss and optimizer configurations. Constructs the forward directed acyclic graph (IrGraph).
  • Phase 2: Analytical Reverse-Mode Autodiff: Traverses the forward graph in reverse topological order. For every forward operation, emits corresponding analytical derivative nodes using symbolic chain rule formulations. Appends parameter gradient update nodes for SGD/Adam. No runtime graph tape or dynamic allocation is ever constructed on the MCU.
  • Phase 2b: Static Numerical Range Analysis (Novelty): Propagates closed interval arithmetic bounds $[a_{\min}, a_{\max}]$ across forward activations and backward gradients. Verifies whether all intermediate values remain within the valid Q15 fixed-point boundary $[-1.0, +0.999969]$. Inserts saturation clamping nodes if overflow ratios exceed threshold.
  • Phase 3: Static Memory Planning & Buffer Reuse: Performs live-range analysis across tensor variables. Nodes with non-overlapping execution lifetimes are assigned overlapping memory offsets in a unified static SRAM pool, guaranteeing peak watermark $\le$ 64KB without malloc().
  • Phase 4: Target C99 Code Emission: Synthesizes unrolled, zero-dependency C99 functions (mtc_forward(), mtc_backward(), mtc_step()) and static weight arrays ready for direct compilation with xtensa-esp32-elf-gcc.

4. Core Algorithms & Mathematical Formulations Section 4

4.1 Reverse-Mode Analytical Automatic Differentiation

MTC synthesizes exact analytical gradient equations at compile time using the multi-variable calculus chain rule, eliminating tape-based runtime overhead:

Operation Forward Formulation Analytically Emitted Backward Derivative
Dense (Linear) $y = W \cdot x + b$ $\frac{\partial L}{\partial W} = x^T \cdot \frac{\partial L}{\partial y}, \quad \frac{\partial L}{\partial b} = \frac{\partial L}{\partial y}, \quad \frac{\partial L}{\partial x} = \frac{\partial L}{\partial y} \cdot W^T$
ReLU Activation $y = \max(0, x)$ $\frac{\partial L}{\partial x} = \frac{\partial L}{\partial y} \odot \mathbb{I}(x > 0) \quad \text{\footnotesize (Binary gate mask)}$
Sigmoid Activation $y = \sigma(x) = \frac{1}{1 + e^{-x}}$ $\frac{\partial L}{\partial x} = \frac{\partial L}{\partial y} \odot \sigma(x) \odot (1 - \sigma(x))$
MSE Loss $L = \frac{1}{n}\sum_{i=1}^n (\hat{y}_i - y_i)^2$ $\frac{\partial L}{\partial \hat{y}} = \frac{2}{n} (\hat{y} - y)$
SGD Parameter Step Parameter Update $W_{\text{new}} = W_{\text{old}} - \eta \cdot \frac{\partial L}{\partial W}, \quad b_{\text{new}} = b_{\text{old}} - \eta \cdot \frac{\partial L}{\partial b}$

4.2 Static Numerical Range Analysis (Interval Arithmetic)

Fixed-point Q15 arithmetic represents signed fractions within the bounded interval $[-1.0, \, 1.0 - 2^{-15}] \approx [-1.0, \, +0.999969]$. Values exceeding this boundary cause catastrophic two's-complement integer wrap-around. MTC bounds all forward activations and backward gradients using closed interval rules $[a_{\min}, a_{\max}]$:

  • Interval Addition: $$[a, b] + [c, d] = [a + c, \, b + d]$$
  • Interval Multiplication: $$[a, b] \times [c, d] = [\min(ac, ad, bc, bd), \, \max(ac, ad, bc, bd)]$$
  • Weight Bounds (Xavier / Glorot Initialization): $$W \in \left[ -\sqrt{\frac{6}{\text{fan}_{\text{in}} + \text{fan}_{\text{out}}}}, \, +\sqrt{\frac{6}{\text{fan}_{\text{in}} + \text{fan}_{\text{out}}}} \right]$$
  • Stability Metric: $$\text{Ratio} = \frac{\max(|a_{\min}|, \, |a_{\max}|)}{\text{Q15}_{\text{MAX}}}$$ Ratios exceeding $1.0$ indicate potential overflow and trigger compile-time saturation clipping.

6.2 Compilation Stage Specifications & Safeguards

Stage Compiler Pass Transformation & Functionality Compile-Time Safeguard
Stage 1 Ingestion & Parser Deserializes model JSON into strongly-typed ModelConfig AST. Rejects invalid JSON syntax and missing fields.
Stage 2 Layer Validator Verifies feature dimension chaining ($W_{i-1}.\text{out} == W_i.\text{in}$) and activation order. Rejects dimension mismatches, 0-feature layers, and orphan activations.

  • Early Syntactic & Structural Rejection: Dimension mismatches ($W_{i-1}.\text{out} \neq W_i.\text{in}$), missing hyper-parameters, and unsupported activation orders are detected at the AST ingestion boundary before DAG construction, returning actionable line/column diagnostics to the developer.
  • Static Deterministic Memory Certification: The static buffer allocator computes precise live ranges across all forward activation tensors and backward adjoints. Any model configuration whose peak watermark exceeds the target 64 KB SRAM budget is rejected at compile time, eliminating embedded runtime crashes.

7.3 Memory Ownership, Lifetime Management & Zero-Allocation Semantics

  • Single-Ownership & Arena Allocation: Rust's affine type system guarantees exclusive ownership of the node arena by IrGraph. Nodes reference operands via usize indices, eliminating pointer chasing and dangling references without runtime GC.
  • Static Buffer Lifetime Reuse: Intermediate forward activations and backward adjoint tensors with non-overlapping liveness intervals share overlapping memory offsets in uint8_t sram_pool[], reducing peak MCU memory by up to 60%.
  • Deterministic Compile-Time Verification: Static memory bounds and numerical intervals are checked during graph lowering. Peak tensor watermarks exceeding 64 KB or uncontrollable Q15 overflows are rejected before code emission.
